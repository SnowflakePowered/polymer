# Formal Verification Candidates

Candidates for formal specification and proof, with the strategy for each.

- **Kani**: bounded model checking of small pure-Rust kernels (codecs, path logic, on-disk formats, arithmetic).
- **TLA+**: cross-process protocols, crash consistency, and concurrency, where bugs are in interleavings rather than code.
- **loom / proptest**: noted where they fit better than either.

Status: TLA+ models written (see the log below). No `kani`, `proptest`, or `loom` dependencies exist in the workspace yet.

## TLA+ log

Specs live in `tla/` beside each crate's `src/` (or beside `lib.rs` for crates without `src/`). Each has a `<Name>.tla` model, an `MC<Name>.tla` with concrete constants, and an `MC<Name>.cfg`. Run with `pwsh -File scripts/tlc.ps1 <crate>/tla/MC<Name>.tla` (`TLA_HOME` defaults to `D:\Tooling\TLA+`, `TLC_WORKERS` defaults to `auto`). Historical counterexamples remain in the log; fixes and replacement models are recorded explicitly.

Vita, 3DS/New 3DS, Wii U, PS3, and Wii now use component histories rather than global NAND history rewriting. Platform composers under `impls` own validation, composition, dependency rules, and generated indexes; Git storage owns revisions and journaled publication. Twenty-eight real-storage integration tests in `crates/runtime/polymer-library/tests/{vita,nintendo,ps3,wii}_histories.rs` pass. New models and exact bounds/results are documented in [NAND component verification](crates/filesystem/polymer-consolestorage/tla/COMPONENTS.md). Wii coverage includes shared-content lifetime, stable UID allocation, IOS-removal dependencies, saved-data preservation, WAD corruption/cancellation, recovery, and independent repository handles. Review also fixed unowned shared-file overwrite, mutable WAD metadata, duplicate WAD content IDs/indices, and per-handle platform-index locking. Firmware snapshots are tested through the public component API, not a real PUP. Game-specific DLC compatibility and host power-loss durability remain unverified.

## Not worth verifying

Hook and vtable crates, D3D/Vulkan/Metal FFI, the Deno runtime, the GUI, `polymer-statistics`, `polymer-banner`. Their correctness depends on external API behavior that would have to be axiomatized.

## Suggested order

1. **K4**: likely a real INI injection bug; confirm first.
2. **K1**: about an hour; flags the known lossy fields.
3. **T3**: protects user saves.
4. **T1**: the most likely to find rare hangs or torn frames.
5. **K6**, **K2**: about an hour each.
6. **K3**: security boundary.
7. **K13**: confirm the root and macOS case-folding gaps.
8. **K12**, **K14**: hostile input and plugin sandbox.
9. **T12**: save data written through composed storage.
10. **K17**, **T13**.

For the shell thread, S1 comes first: traces (a) and (c) are quick to reproduce by hand before writing any spec.
